# GameMonetize publisher integration

## Current source

The catalogue refresh uses the JSON feed generated by the authenticated Publisher Game Feed page:

`https://gamemonetize.com/feed.php?format=0&page={page}`

The feed returns up to 2,000 records per page. The importer advances pages until the first short page, applies retries and rate-limit backoff, and never runs during a player request.

The generated feed URL is generic. It contains no publisher ID, website ID, affiliate parameter or account token. Feed records provide supplier ID, title, description, instructions, category, tags, artwork, exact embed URL, width and height.

## Revenue attribution evidence

The authenticated Publisher dashboard showed:

- Website: `gr8gamz.com`
- Status: Approved
- ads.txt: Verified
- Publisher reporting organized by approved website
- No account identifier in the generated feed URL or generated game URL
- Exact game URLs on `https://html5.gamemonetize.co/`

Revenue attribution uses the approved referring website. The feed and embeds contain no publisher identifier, and none is invented. The site owner has explicitly authorized production activation using the approved `gr8gamz.com` website and verified ads.txt as the attribution basis. The dashboard does not separately list `www.gr8gamz.com`; that remains recorded as an unverified subdomain detail rather than being misrepresented as a separate approval.

## Activation controls

Publication requires both build-time controls:

- `GR8_GAMEMONETIZE_REVENUE_VERIFIED=true`
- `GR8_ENABLE_GAMEMONETIZE_EMBEDS=true`

Both controls are enabled by the production catalogue refresh workflow under the owner's approved-domain authorization. They must remain paired so a partial configuration cannot accidentally publish or load provider records.

## Security and consent

- Parent CSP permits only `https://html5.gamemonetize.co` for frames and `https://img.gamemonetize.com` for artwork.
- The parent page does not load GameMonetize scripts.
- Exact feed-supplied HTTPS embed URLs are retained without hostname rewriting.
- GameMonetize frames require the existing GR8 GAMZ consent state to be `accepted`.
- Reject All and an unknown choice never create a GameMonetize iframe.
- The provider controls its own in-game advertising. GR8 GAMZ adds no provider overlay or manual popup.

## Why the legacy integration failed

The retired importer requested six overlapping 100-game popularity slices from the old RSS endpoint. It produced 505 records, searched feeds by title at runtime and could resolve stale or ambiguous entries. Some URLs were also previously rewritten between `.co` and `.com`; an iframe `load` event then incorrectly counted browser error documents as success.

The replacement uses the complete paginated publisher feed, stable supplier IDs, exact feed URLs, offline validation, deterministic deduplication and explicit quarantine states. Public requests read only the generated registry.

## Daily refresh

`.github/workflows/refresh-gamemonetize-catalogue.yml` runs once daily. It fetches the current feed, validates and deduplicates it, soft-disables disappeared records, and opens a draft pull request only when generated catalogue data materially changes. It never auto-merges.
